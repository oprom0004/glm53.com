## 二、真实实战场景：Docker 网络分区故障自主排查

在生产级 DevOps 中，模型必须能够解析真实终端返回的非结构化错误，并连续执行多步排查：

```
[运维告警] ──► [GLM-5.3 终端 Agent]
                       │
                       ├─ 1. 执行: docker inspect app_gateway
                       ├─ 2. 解析 JSON: 发现 bridge 网络 IP 冲突
                       ├─ 3. 执行: iptables -L -n -v
                       ├─ 4. 诊断: 发现 DOCKER-USER 链丢包规则
                       ├─ 5. 自动修复: iptables -D DOCKER-USER 2
                       └─ 6. 回归验证: curl -I http://internal-service ➔ 200 OK
```

### 为什么 GLM-5.3 能够自主诊断此类难题？
1. **真实 Bash 交互轨迹预训练**：预训练阶段注入了 500 万轮由资深 SRE 工程师完成的 Linux 诊断会话，模型对 `strace`、`netstat`、`tcpdump` 的输出具有极高敏感度；
2. **状态机长记忆维持**：传统模型在执行 5 步以上的终端指令后，极易遗忘第一步保存的临时环境变量；GLM-5.3 依靠 100 万字上下文保证无论交互多少轮，系统初始拓扑与上下文绝对保真；
3. **安全沙盒拦截机制**：针对 `rm -rf /`、未受限的 `dd` 磁盘写入等高危指令具有原生防火墙识别能力，输出拒绝警告并引导执行安全排查。

## 三、生产环境 Agent 快速调用脚本

使用 Python 编写自动化终端 Agent：

```python
import os
import subprocess
from openai import OpenAI

client = OpenAI(
    base_url="https://api.glm53.com/v1",
    api_key=os.environ.get("GLM_API_KEY")
)

def execute_sandboxed_bash(command: str) -> str:
    """在隔离 Docker 沙盒中执行 Shell 指令"""
    result = subprocess.run(
        ["docker", "exec", "sandbox_container", "bash", "-c", command],
        capture_output=True,
        text=True,
        timeout=30
    )
    return result.stdout or result.stderr

tools = [{
    "type": "function",
    "function": {
        "name": "execute_sandboxed_bash",
        "description": "在安全的 Linux 容器沙盒中运行终端 Shell 命令并捕获输出",
        "parameters": {
            "type": "object",
            "properties": {"command": {"type": "string", "description": "要执行的 Shell 指令"}},
            "required": ["command"]
        }
    }
}]

# 发起自主排查会话
response = client.chat.completions.create(
    model="z-ai/glm-5.3",
    messages=[
        {"role": "system", "content": "你是一位顶级 Linux SRE 工程师。你可以使用终端工具自主排查并修复系统问题。"},
        {"role": "user", "content": "我们的 Nginx 反向代理返回 502 Bad Gateway，请在沙盒中排查上游服务状态并修复。"}
    ],
    tools=tools,
    tool_choice="auto"
)
```
