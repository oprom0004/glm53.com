# 100 万 Token 全库代码分析方案：告别切片 RAG，一次性装载 500 个工程源文件

**核心结案结论**：在软件工程分析领域，**传统基于向量相似度的切片 RAG（Retrieval-Augmented Generation）存在无法逾越的致命缺陷——它会彻底打碎跨文件函数调用链、破坏全局类型系统并丢失环境变量隐式绑定**。GLM-5.3 提供了 **1,000,000 Token（100 万字）** 的原生上下文窗口，支持将多达 **500 个源代码文件、10 万行工程代码一次性完整装载**。结合 MLA（多头潜在注意力）技术，在权威的 1M 大海捞针（Needle-In-A-Haystack）测试中实现了 **99.8% 的无损精准召回**，实现真正的“全景全局推演”。

## 二、生产级全库打包脚本 (`repo2prompt.py`)

为了将整套工程代码结构化地转换为适合 GLM-5.3 处理的格式，我们提供以下官方推荐的 Python 打包工具：

```python
import os
import pathspec

def collect_repository(root_dir: str, output_file: str, max_file_size_kb: int = 500):
    """
    遍历代码仓库，遵循 .gitignore 规则，将所有源文件结构化打包为适合 1M 上下文的 XML 格式。
    """
    ignore_spec = None
    gitignore_path = os.path.join(root_dir, '.gitignore')
    if os.path.exists(gitignore_path):
        with open(gitignore_path, 'r', encoding='utf-8') as f:
            ignore_spec = pathspec.PathSpec.from_lines('gitwildmatch', f)

    file_entries = []
    tree_lines = []

    for dirpath, dirnames, filenames in os.walk(root_dir):
        # 排除 .git 与 node_modules
        if '.git' in dirnames:
            dirnames.remove('.git')
        if 'node_modules' in dirnames:
            dirnames.remove('node_modules')

        for filename in filenames:
            rel_path = os.path.relpath(os.path.join(dirpath, filename), root_dir).replace('\\', '/')
            if ignore_spec and ignore_spec.match_file(rel_path):
                continue

            full_path = os.path.join(dirpath, filename)
            if os.path.getsize(full_path) > max_file_size_kb * 1024:
                continue

            try:
                with open(full_path, 'r', encoding='utf-8', errors='ignore') as f:
                    content = f.read()
                    file_entries.append((rel_path, content))
                    tree_lines.append(rel_path)
            except Exception:
                continue

    with open(output_file, 'w', encoding='utf-8') as out:
        out.write("<repository_index>\n")
        out.write("\n".join(tree_lines))
        out.write("\n</repository_index>\n\n")

        for path, code in file_entries:
            out.write(f'<file path="{path}">\n')
            out.write(code)
            out.write("\n</file>\n\n")

    print(f"成功打包 {len(file_entries)} 个文件至 {output_file}！")

if __name__ == "__main__":
    collect_repository(".", "codebase_1m_payload.txt")
```

## 三、倒三角 1M Prompt 黄金架构布局

将打包生成的内容发送给 GLM-5.3 时，务必遵守以下布局：

```xml
<!-- 1. 系统角色指令 (Top) -->
<role_directive>
你是一位世界顶尖的系统架构师。你将审查以下全库源码。
所有修改建议必须严格保持类型兼容，并以统一 Git Diff 格式输出。
</role_directive>

<!-- 2. 全局目录索引树 -->
<repository_index>
src/core/auth.ts
src/core/db/pool.ts
src/server/router.ts
... (500 个文件索引)
</repository_index>

<!-- 3. 百万字全量文件内容 -->
<file path="src/core/db/pool.ts">
... (文件源码)
</file>
... (其余文件)

<!-- 4. 具体任务指令 (Bottom: 极度关键，必须放最底部) -->
<task_instruction>
请分析从 `router.ts` 接收到 WebSocket 请求，到 `pool.ts` 释放连接的全链路。
当发生瞬时断网重连时，是否存在连接泄露？
请列出调用栈证据，并输出修复该 Bug 的最小 Git Diff 补丁。
</task_instruction>
```
