# 视频每秒积分配置

业务依据：用户要求对照 `wanai30-studio` 的后台每秒积分设置；参考 Studio 的 `src/shared/services/wan-pricing-settings.ts` 和视频定价字段。Lite 原有计费规则及默认值不变。

## 使用

超级管理员登录后进入 `/zh/admin/settings/pricing#video-rates`（后台 → 设置 → 定价与积分 → 视频生成消耗积分）。与上方商品售价、购买积分独立保存。

- Wan 2.5、2.6、2.7：分别配置文生视频/图生视频的 480P、720P、1080P。
- Wan 3.0 Standard、Prime：分别配置 480P、720P、1080P，文生/图生共用同规格费率。
- 共 24 项。每秒积分支持 1–99999.5，整数或 0.5 步进；留空并保存会禁用对应规格，不代表免费。
- 总积分按整段视频向上取整：例如 3.5 积分/秒 × 3 秒 = 11 积分。
- 默认费率不变；Wan 2.5 的 1080P 默认留空。接口/模型是否支持某规格仍由供应商能力决定，填写费率不代表供应商支持该规格。

## 生效和权限

- 服务端页面及 API 重新校验有效超级管理员角色。普通管理员不能通过通用设置写入每秒积分或新费率快照。
- 保存后，后续报价及新任务提交读取最新配置。原有报价金额、版本检查继续生效；已有任务的扣费、重放和退款使用已保存记录，不追溯改价。
- 无新快照时，兼容原 24 项数据库字段和默认值。首次保存整份费率到 `config.wan_pricing_video_rates`，无需数据库迁移，不删除旧字段。
- 24 项作为一个带版本的 JSON 原子保存。多个窗口/管理员同时编辑时，后提交的旧版本被拒绝，需显式重新载入后再编辑。
- 非空环境变量覆盖对应数据库费率，界面显示生效值并设为只读。后台保存其他费率不会把临时环境覆盖复制到数据库；移除覆盖后恢复底层保存值。密钥和供应商接口地址不进入此响应。
- 保存超时或网络结果不明时，保留草稿、阻止直接重试，要求重新读取服务器保存值。重新载入会替换当前草稿；会话失效时锁定保存。
- 商品和视频费率分别保存，但共用页面离开保护；任一表单请求进行中都会提示请求可能已在服务端完成。关闭页面只取消浏览器等待，不承诺撤销服务端保存。

## 验证方式

服务端测试使用临时数据库，不修改真实费率或用户数据。浏览器隔离预览复用真实表单，但保存只更新内存：

```sh
node scripts/fixtures/video-rates-preview.mjs
```

要求本地开发服务已运行于 3000；预览仅监听 `127.0.0.1:3108`。可用 `locale=en`、`theme=dark`、`scenario=slow|conflict|offline` 检查界面，不用于部署或正式管理操作。
