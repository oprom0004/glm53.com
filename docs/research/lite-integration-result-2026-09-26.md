## 已接入

- Wan 2.5、2.6、2.7、3.0 生成器及各版本参数限制。
- 服务端报价、参考图上传、任务提交、查询、结果保存和异常恢复。

- 后台 AI 接口、R2、商品定价、积分额度及视频积分费率配置。

生成器已使用业务接口，原来的计时器和固定演示视频不再充当生成结果。真实调用仍依赖外部服务配置。

## 合并时额外处理

- 旧定价组件改为读取统一商品目录，避免继续发送旧版结账字段。
- 原通用任务查询及刷新页面接入 Wan 专用恢复逻辑，并校验任务归属；通用任务仅状态变化时也会持久化。
- 定价数据不可用时显示明确提示，不展示无法确认的旧价格；首页及定价页不共享缓存可变商品目录。
- 浏览器认证使用当前访问站点地址，服务端使用 `AUTH_URL`，避免本地页面因原生产配置而向正式站发送登录请求。
- 字体改用相同家族的本地文件，生产构建无需下载 Google 字体。
- 保留原首页各区块导航，加入各版本、定价和账户入口；小屏幕缩减品牌文字，给操作按钮留出空间。
- Windows 测试结束时关闭数据库连接，并回收 libSQL 原生事务句柄，使临时数据库可以正常清理。

## 保留与运行配置

`.env`、`.dev.vars` 和 `data/local.db` 均与备份一致。未复制 lite 的用户、管理员角色或密钥。原 `public` 素材全部保留；静态 `public/sitemap.xml` 已由 `src/app/sitemap.ts` 替代，避免路由冲突。

当前本地数据库没有用户和服务配置。开始使用时：

1. 按根目录 README 设置本地访问地址并启动，注册自己的账户。
2. 初始化角色，再为自己的账户分配 `super_admin`。
3. 在后台配置 Wan 视频接口及实际模型 ID、R2 和 Stripe；Google 登录按需配置。
4. 用真实服务完成一次小额测试购买、积分入账、视频生成及失败恢复验收，再准备上线。

详细字段说明见 `docs/configuration.md` 与 `docs/video-credit-rates.md`。

现有实现只为新结账启用 Stripe，只为业务存储启用 R2，注册默认不赠送积分。内部 `polaris_*` 字段和 Stripe `wanai_app=wanai30-lite` 标记保留兼容性，不应仅为名称统一而改动。

当前视频和支付业务依赖事务，Cloudflare D1 不支持该实现。视频恢复使用 Node 进程内调度，部署环境必须支持持续执行或另行适配。此次没有发布线上版本。
